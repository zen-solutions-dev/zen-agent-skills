# Run the adopter's own pre-PR gate early, on the person's computer

**Lesson, 2026-11-26**, from rollout round 3 ([plan](../../reviews/2026-11-25-rollout-r3-plan.md)). In the Zen product app (a private repository), two branches verified by cloud sessions on 2026-11-25 could not be opened as pull requests: the adopter's pre-PR gate needs a git-ignored list held only on the maintainer's computer. When a session there ran the gate on 2026-11-26, the gate's own test suite failed on that Windows checkout for two reasons unrelated to the branches: a test regex that assumed LF line endings, and the maintainer's global git hook refusing the fake-token commits the secret-scan tests make. The fix (in the adopter, as its own quest) gave each throwaway test repository its own empty hooks path and accepted CRLF. It cost one extra quest and a restack of two branches.

So: in an adopter whose gate is local-only, run that gate once on the person's computer before the first child is briefed, and treat a red gate there as the first quest. Recorded in `docs/INSTALL.md` (the early question, `chore-0119`) for the local-only case; the "run it once first" half is not yet in `orchestrate`.
